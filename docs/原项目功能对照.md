## 一、手机专属、网页版不需要（共 12 类）

| 原项目做法 | 网页版为什么不需要 |
|---|---|
| `adb devices` 选设备、多设备输入编号 | 只有一个浏览器 |
| `get_device_resolution` 分辨率换算 | 用 DOM 选择器，不点坐标 |
| `find_y_offset` 偏移值自学习（截图找"说点什么"逐值试探，连续 6 次失败取平均） | 不需要坐标 |
| `check_detail_height` / `check_fudai_detail_height` 按颜色判断任务数（3/2/1/0） | 面板文字直接读 |
| `deal_robot_pic` / `check_robot_pic_distance` 图像二值化算滑动距离 | 网页版是验证码页 → 识别后暂停并提醒人工 |
| `check_stop_charging`(vivo) / `deal_battery_level`(电量<30 挂 30 分钟) | 电脑没有电池 |
| `get_screenshot`(adb 截图 2 秒) | CDP 直读 DOM，0 延迟 |
| `start/stop_douyin_app` / `restart_and_reset` | 换成换标签/重载页面 |
| `input_text`(adb 输入) | 页面 `Input.insertText` / 真实按键 |
| OCR（PaddleOCR）识别一切 | 全部文本都在 DOM 里 |
| 上划切直播间 / 返回键 | 直接导航 URL |
| 分辨率比例截图裁剪 | 不需要 |

## 三、我们比原项目强的地方
1. **不需要 OCR / 截图 / adb**：全部读 DOM，延迟从"2 秒截图"降到毫秒级；
2. **不点坐标**：抗布局变化、抗分辨率；
3. **风控更稳**：识别验证码页 → 自动降频 + 提醒人工；
4. **可观测**：每一步都写诊断日志 + 记录文件，出问题能对账；
5. **不靠猜**：参与后**回头确认**才算成功（原项目是"点了就算"）。

## 四、仍然做不到 / 有意不做的
1. **自动下单领实物奖**：涉及填写收货地址、可能产生订单，风险太高 → 检测到中奖只截图+提醒，**由你手动完成**；
2. **自动过点击/人脸验证**：原项目是"退出去等 30 分钟"，我们也是暂停+提醒；
3. **多设备同时挂**：网页版可以后续支持多浏览器实例，暂不做。
